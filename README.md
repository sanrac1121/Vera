# magicpin AI Challenge — Merchant AI Assistant ("Vera")

**Submission by**: Team Antigravity  
**Model Architecture**: Multi-context LLM Prompt Composition Engine (Gemini 2.0 / 1.5 Flash)  
**Target Platform**: WhatsApp Merchant Outreach (magicpin India)

---

## 1. Executive Summary & Approach

Vera is magicpin's merchant AI assistant, tasked with driving high-compulsion, contextual WhatsApp engagement across ~100,000 Indian merchant partners across 5 key verticals: **Dentists, Salons, Restaurants, Gyms, and Pharmacies**.

Our solution addresses production Vera's biggest failure modes (auto-reply loops, intent-handoff friction, generic discount copy, and low engagement frequency) by introducing a **4-Context Layer Architecture** powered by strict domain rules, localized Hinglish code-mixing, and data-anchored compulsion levers.

---

## 2. System Architecture & 4-Context Pipeline

Every WhatsApp message generated by `bot.py` is dynamically synthesized from four structured context layers:

```
                  ┌─────────────────────────────────────┐
                  │ 1. CategoryContext  (Domain Rules)  │
                  │ 2. MerchantContext  (State & Stats) │ ──► bot.compose() ──► ComposedMessage
                  │ 3. TriggerContext   (Why Now Event) │
                  │ 4. CustomerContext  (Optional)      │
                  └─────────────────────────────────────┘
```

1. **CategoryContext**: Implements vertical-specific voice profiles, allowed medical/technical vocabularies, legal taboos (e.g., prohibition of guarantees in clinical verticals), peer benchmarks (CTR, ratings), and weekly research digests.
2. **MerchantContext**: Integrates live merchant metrics (views, calls, CTR deltas), active/expired catalog offers, dormant signals, and language preferences.
3. **TriggerContext**: Captures external beats (festivals, heatwaves, CDE webinars) and internal performance signals (CTR dips, review milestones, recall windows).
4. **CustomerContext**: Formulates customer-facing messages sent on behalf of the merchant (`send_as="merchant_on_behalf"`) respecting appointment slots and soft-lapsed recall intervals.

## 3. Key Technical & Prompt Engineering Innovations

### A. Specificity & Verifiability over Generic Copy
Rather than generic promotional pitches ("Flat 30% off"), messages are strictly anchored to verifiable context facts (e.g., *"JIDA Oct trial: 2,100 patients, 38% reduction"* or *"Haircut @ ₹99"*).

### B. Domain Voice Matching
- **Dentists**: Clinical, peer-to-peer tone with `"Dr. [FirstName]"` honorifics and technical vocabulary (`caries recurrence`, `fluoride recall`).
- **Salons**: Warm, practical, inviting tone.
- **Restaurants**: Operator-to-operator focus on footfall and thali/delivery volume.
- **Gyms**: Motivational, coaching-oriented.
- **Pharmacies**: Precise, reliable, and trustworthy.

### C. Multi-Turn Auto-Reply & Intent Handoff Management (`conversation_handlers.py`)
- **Auto-Reply Loop Prevention**: Detects WhatsApp Business automated boilerplate text (*"Thank you for contacting us..."*). Immediately terminates outreach on consecutive auto-replies (`action="end"`) to save merchant turns.
- **Intent Handoff Acceleration**: Detects explicit commitment signals (*"I want to join"*, *"Let's do it"*). Switches immediately from pitch/qualification mode to execution mode (*"Done! Profile updated"*).

## 4. Benchmark Submission & File Manifest

- **`bot.py`**: Core entrypoint function `compose(category, merchant, trigger, customer)` with structured JSON schema enforcement and graceful fallback logic.
- **`conversation_handlers.py`**: Multi-turn dialogue handler `respond(state, merchant_message)` for replay test compliance.
- **`server.py`**: Flask HTTP server running on `http://localhost:8080` exposing `/v1/healthz`, `/v1/metadata`, `/v1/context`, `/v1/tick`, and `/v1/reply`.
- **`submission.jsonl`**: Formatted outputs for all 30 canonical benchmark test pairs (`T01`–`T30`).
- **`judge_simulator.py`**: LLM judge evaluation script.
